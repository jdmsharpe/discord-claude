# Discord Claude Bot - Developer Reference

## Quick Start

```bash
uv sync --extra dev                   # creates .venv from uv.lock (no pip inside — use `uv pip` if needed)
cp .env.example .env                  # then fill in required values
git config core.hooksPath .githooks   # enable repo pre-commit hook
uv run python src/bot.py   # or: docker compose up --build
```

## Gotchas

- Uses **`py-cord`** (not `discord.py`). The slash-command API differs; don't mix docs between the two.
- `GUILD_IDS` must list at least one guild ID. Empty or unset parses to `[]`, and py-cord only registers a command globally when its `guild_ids is None`, so an empty list registers the commands **nowhere** — not globally, not per-guild. `validate_required_config()` does not check it, so the bot starts clean with no commands.

## Environment Variables

| Variable | Required | Description |
| --- | --- | --- |
| `BOT_TOKEN` | Yes | Discord bot token |
| `GUILD_IDS` | Yes | Comma-separated Discord server IDs; at least one is required — empty or unset registers no commands at all (not enforced at startup) |
| `ANTHROPIC_API_KEY` | Yes | Anthropic API key |
| `SHOW_COST_EMBEDS` | No | Show cost embeds (`true`/`1`/`yes`, default: `true`) |
| `MEMORIES_DIR` | No | Per-user memory directory (default: `./memories`) |
| `ANTHROPIC_MCP_PRESETS_JSON` | No | Inline JSON of named MCP presets |
| `ANTHROPIC_MCP_PRESETS_PATH` | No | Path to JSON file of named MCP presets |
| `CLAUDE_PRICING_PATH` | No | Override the bundled `src/discord_claude/config/pricing.yaml` |
| `LOG_FORMAT` | No | `text` (default) or `json` for structured JSON-lines output |
| `SAFETY_IDENTIFIER_SECRET` | No | Key for the per-user `metadata.user_id` identifier (default: a key derived from `BOT_TOKEN`; see Provider Notes); must not equal `ANTHROPIC_API_KEY` |

## Supported Entry Points

- Launcher: `python src/bot.py` remains supported and delegates to `discord_claude.bot.main`.
- Cog composition contract:

  ```python
  from discord_claude import ClaudeCog

  bot.add_cog(ClaudeCog(bot=bot))
  ```

  `ClaudeCog.__init__` calls `validate_required_config()` automatically, so config is validated at cog construction regardless of whether `main()` is used. Note: `GUILD_IDS` format is validated at import time (it is captured at class-definition time by `SlashCommandGroup`); `BOT_TOKEN` and `ANTHROPIC_API_KEY` missing or blank values, and a `SAFETY_IDENTIFIER_SECRET` equal to `ANTHROPIC_API_KEY`, are validated at construction time.
- `discord_claude` and `discord_claude.cogs.claude` both use lazy `__getattr__` exports so helper imports do not eagerly pull in Discord-heavy modules. Type-only imports keep `pyright src/` aware of those public exports.

## Provider Notes

- Memory storage root is resolved via `discord_claude.cogs.claude.paths`.
- Tool metadata (Anthropic payload, UI label/description, execution mode) lives in `discord_claude.cogs.claude.tool_registry.TOOL_REGISTRY`. Adding a tool requires only a new `ToolRegistryEntry` there; `get_anthropic_tools` and `get_tool_select_options` derive the API and UI views automatically.
- Client-side tool dispatch lives in `ClaudeCog._execute_tool`, which looks up handlers in the per-cog `_tool_handlers` dict (initialized from `default_tool_handlers()` in `discord_claude.cogs.claude.tool_handlers`). The `memory` handler calls through `discord_claude.memory` so tests can patch the live owner. Use `cog.register_tool_handler(name, handler)` / `cog.unregister_tool_handler(name)` to extend or replace handlers at runtime.
- Conversations remain keyed by `(user_id, channel_id)`.
- **Per-user identifier (`metadata.user_id`, 2026-10-08):** every Messages request made for a Discord user carries `metadata={"user_id": <identifier>}`: each request of `call_api_with_tool_loop` (`chat.py`; set once on `api_params`, so both the `beta.messages.create` and `messages.create` paths and every tool-loop iteration send it, for `/claude chat` and follow-up messages alike) and the manual-compaction summarizer call (`compact_conversation(..., user_id=...)`, `state.py`). The identifier is `build_safety_identifier(user_id)` (`util.py`): `HMAC-SHA256(key, str(user_id).encode()).hexdigest()`, 64 lowercase hex characters. The key is `SAFETY_IDENTIFIER_SECRET` (UTF-8) when set and non-empty, otherwise `HMAC-SHA256(BOT_TOKEN, b"safety-identifier-v1")`; with neither, `request_metadata` returns None and no `metadata` is sent. The Anthropic API key is never key material (Anthropic holds it): `validate_required_config` (`config/auth.py`) raises `RuntimeError` when `SAFETY_IDENTIFIER_SECRET` equals `ANTHROPIC_API_KEY` (the message includes neither value), as discord-openai, discord-openrouter and discord-grok do. Neither the raw ID nor an unkeyed hash is sent, and neither the key nor the identifier is logged. The memory tool stores files under `<MEMORIES_DIR>/<discord user id>/`, and an OSError message names that absolute path; its result goes back to Anthropic as a `tool_result` in the same tool loop, so `_without_user_dir` (`memory.py`) replaces the user directory with `/memories` in every error result of `execute_memory_operation` and `_list_directory`, and replaces a message that still contains the ID with a fixed one. Before this, creating `/memories/a.txt/b.txt` under an existing file `a.txt`, renaming a directory into itself or a file name that is too long returned the absolute path with the raw ID. The construction, the env var name and the `safety-identifier-v1` label are the same as in discord-openai, discord-openrouter and discord-grok; change them together. Limit: the Messages API reference (https://platform.claude.com/docs/en/api/messages/create, checked 2026-10-08) gives `metadata.user_id` "maxLength: 512" and asks for "a uuid, hash value, or other opaque identifier", so the 64-character value is sent untruncated. In anthropic 1.12.1, `metadata` is a parameter of `messages.create` / `stream` / `parse` and `beta.messages.create`, not of `count_tokens` (the bot calls no `count_tokens`). Live 2026-10-08: requests with `metadata.user_id` set returned 200 on Opus 5.5 (the bot's full beta shape), Opus 4.5, Haiku 4.5 and the Haiku 5.5 summarizer. Pinned by `tests/test_safety_identifier.py` (both API surfaces, every tool-loop iteration, the summarizer, the slash-command and follow-up paths, no `metadata` without a key, raw ID in no request), `TestSafetyIdentifier` / `TestDeriveSafetyIdentifierKey` in `tests/test_util.py` (including the env override and `BOT_TOKEN` fallback through a fresh import of `config.auth` and `util`, and `test_fixed_vectors_shared_with_sibling_bots`: two literal 64-hex values for user 111222333 that discord-openai, discord-openrouter and discord-grok also produce), the `SAFETY_IDENTIFIER_SECRET` cases in `tests/test_config_auth.py` (including `test_validate_required_config_rejects_the_api_key_as_safety_secret`), and `TestErrorMessagesOmitUserId` in `tests/test_memory.py`. `test_calculate_cost_uses_fallback_for_unknown_model` (`tests/test_config_pricing.py`) re-imports `util` and now restores the original module afterwards; before, later tests that patched `discord_claude.util` patched a different module object than the one the cog code had imported.
- Named MCP presets are loaded from `ANTHROPIC_MCP_PRESETS_JSON` (inline JSON) and/or `ANTHROPIC_MCP_PRESETS_PATH` (path to a JSON file); both are additive and duplicate preset names across them are rejected at startup.
- Claude MCP presets support only `url` (HTTPS), `authorization_env_var` (user-defined runtime token env var), `allowed_tools`, and `defer_loading` — no `kind` discriminator or approval loop.
- MCP state persists independently from built-in tool names via `mcp_preset_names` on `ChatCompletionParameters`.
- Anthropic MCP traffic is passed through with `mcp_servers` and `mcp_toolset`, and `call_api_with_tool_loop` adds the `mcp-client-2025-11-20` beta when MCP is active.
- MCP content blocks are ignored by the local tool loop; only built-in Anthropic tool calls are executed client-side.

- **Server-side compaction:** `COMPACTION_MODELS` (`util.py`: Fable 5.1, Fable 5, Opus 5.5, Opus 5, Sonnet 5.5, Sonnet 5, Haiku 5.5, Opus 4.8 / 4.7 / 4.6, Sonnet 4.6; the two 5.5 models accepted `compact_20260112` on 2026-10-08) opt into the `compact-2026-01-12` beta with a `compact_20260112` edit in `call_api_with_tool_loop`. The summarizer call is now billed: `compact_conversation(..., usage_totals=totals)` adds its usage through `UsageTotals.accumulate_compaction_summary` under `COMPACTION_SUMMARY_MODEL`, billed at the summarizer's rates and included in the cost embed's token counts; before, it was discarded. Pinned by `test_manual_compaction_counts_cached_prompt_tokens`, `test_manual_compaction_uses_the_latest_prompt_not_the_turn_total` and `test_manual_compaction_bills_the_summarizer_call` in `tests/test_claude_chat.py` (the first two fail against the old trigger), and `test_prompt_tokens_is_the_full_prompt_of_the_latest_response` / `test_accumulate_compaction_summary_bills_at_the_summary_model` in `tests/test_util.py`. **No summary, no compaction (2026-10-08):** `compact_conversation` used to clear the history and replace it with the response's text, or with a fixed "could not be parsed" note, whenever `parsed_output` was not a `ConversationSummary` — a summarizer refusal, an empty response, or JSON cut off at `max_tokens` lost the whole conversation. It now requires response text that validates as a `ConversationSummary`; otherwise it logs a warning with the `stop_reason`, leaves `messages` unchanged and returns None. It does the same when the call raises `anthropic.APIError`; such a call returns no usage, so it adds nothing to the cost. **Summarizer call shape:** `compact_conversation` calls `messages.create` with `output_config=SUMMARY_OUTPUT_CONFIG` (`state.py`: `{"format": {"type": "json_schema", "schema": transform_schema(ConversationSummary)}}`, the same body `messages.parse(output_format=ConversationSummary)` sends), adds the response's usage to the turn, and only then validates the text with `ConversationSummary.model_validate_json` (`_render_compaction_summary`). It used `messages.parse` until 2026-10-08, which runs `TypeAdapter.validate_json` inside the SDK (`anthropic/lib/_parse/_response.py`) and raises pydantic's `ValidationError` for any text block that is not valid JSON for the schema — an empty text block, JSON cut off at `max_tokens`, or a refusal written as prose or as partial JSON (checked against anthropic 1.12.1's `parse_response`; only a refusal with no content returned a response with `parsed_output` None). - **Retry**: the `AsyncAnthropic` client is built with `max_retries=4, timeout=300` (total 5 attempts) in `client.py`; transient 429/5xx/connection errors recover transparently via the Anthropic SDK's built-in exponential backoff.
- **Conversation TTL**: `prune_runtime_state` in `cogs/claude/state.py` evicts conversations older than `CONVERSATION_TTL` (12h) every 15 minutes via `@tasks.loop`. Caps at `MAX_ACTIVE_CONVERSATIONS`. Daily costs retained for `DAILY_COST_RETENTION_DAYS` (30).
- **Request IDs**: `cog_before_invoke` (and `on_message`) bind a fresh 8-char hex id via `discord_claude.logging_setup.bind_request_id`. All downstream `logger.info`/`warning`/`error` calls automatically include the id. Set `LOG_FORMAT=json` for JSON-lines output.
- **Async file I/O**: blocking `open()` and `pathlib` methods (`read_bytes`, `write_bytes`, `unlink`, etc.) inside `async def` freeze the Discord event loop and stall every concurrent slash command. Wrap them with `asyncio.to_thread(...)` so the I/O runs on a worker thread. Enforced by `ruff` (`ASYNC230`/`ASYNC240`).
